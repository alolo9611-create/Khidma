## Description

```
As the system, I want to calculate due dates using the service's working-day SLA so that every submitted request has a consistent deadline.

Traceability: BR-11
Open questions to resolve: Exact time-of-day dueAt convention and whether submission day counts as day zero should be confirmed.
```

## Acceptance Criteria

```
Given a submission timestamp and slaDays, when calculating dueAt, then Sunday–Thursday count as working days, Friday/Saturday are skipped, Friday/Saturday submissions start counting Sunday, and no holidays are excluded. (BR-11)
```

## PRD requirements (quoted from `Khidma-PRD-Lite.pdf`)

- **F-16 (§05 backlog):** F-16 Due-date calculator — "Pure function: submit time + N working days → dueAt; set on submit." Rule: BR-11. Size: S.
- **BR-11 (§04):** "dueAt = submit time + the service's slaDays working days. Working days are Sunday–Thursday; a request submitted on Friday or Saturday starts counting on Sunday. No holiday calendar."
- **T-01 (§03):** DRAFT → SUBMITTED · Submit · Applicant — "Form valid, mandatory documents declared, no duplicate open request. Sets reference no. and due date." (BR-01 02 03 11)
- §01: "one timezone everywhere (config, default Asia/Riyadh)"
- §06: "An injected Clock — no direct now() — so SLA tests run instantly."
- §03: "The SLA due date never pauses — keeping time simple is a deliberate choice for the bootcamp."
- **Golden rule (§00):** "Where this document is silent, write an open question — never let the agent decide product behaviour."
